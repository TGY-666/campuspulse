# CampusPulse 部署指南

面向评审期的在线演示部署。三种方式按场景选：

| 场景 | 方式 | 耗时 |
|---|---|---|
| 有云服务器（1核2G 起） | [Docker](#一docker-部署推荐) | 15 分钟 |
| 服务器没装 Docker | [systemd 裸机](#二裸机-systemdlinux) | 20 分钟 |
| 只在自己电脑上给别人看 | [本地内网演示](#三windows-本地演示) | 5 分钟 |

**共同前提**：作品要求"评审期间保持服务可用"。所以无论哪种方式，都要先把下面这份环境变量定清楚。

---

## 一、环境变量

配置项在 `campuspulse/config.py` 里读环境变量，`.env` 文件会在启动时自动加载。

```bash
# ---- 必填 ----
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx    # AI 能力；不填则整站降级为规则陈述
CP_AUTH=1                                # 开登录：评审要看的四角色权限矩阵靠它
CP_SECRET_KEY=请换成一串随机字符          # 会话签名密钥；不填会自动生成到 data/.session_key

# ---- 建议 ----
CP_HOST=0.0.0.0                          # 容器/云服务器必须；本地默认 127.0.0.1
PORT=8000
CP_WARMUP=1                              # 启动预热，首次提问不用等冷启动
CP_TOOL_CHANNEL=local                    # local=进程内直调；mcp=走 MCP 协议
CP_VISION=paddle                          # 截图 OCR 引擎：paddle / api / off

# ---- 可选 ----
CP_TENANT_ENFORCE=1                      # 多租户隔离（CP_AUTH=1 时默认开）
CP_CITATION_GUARD=1                      # 引用核验强制模式
```

> **不要把带真实 key 的 `.env` 提交进仓库**。仓库里只有 `.env.example` 模板。

## 二、Docker 部署（推荐）

### 2.1 构建与启动

```bash
git clone <仓库地址> campuspulse && cd campuspulse
cp .env.example .env && vim .env          # 填 DEEPSEEK_API_KEY / CP_SECRET_KEY
docker compose up -d --build
docker compose logs -f                    # 首次会看到"导入 2 个内置数据集（约十几秒）"
```

镜像构建默认带扩展依赖（`WITH_EXT=1`）。想瘦身到 350MB：

```bash
# 改 docker-compose.yml 里的 WITH_EXT 为 "0"，然后
docker compose up -d --build
```

此时截图导入会提示"未检测到 OCR 引擎"，其余功能不受影响。

### 2.2 建演示账号

```bash
# 四角色账号（admin 已在首次启动自动生成，密码在 data/initial_admin.txt）
docker compose exec campuspulse python tools/seed_demo_tickets.py \
    --with-accounts --reset-passwords
docker compose exec campuspulse cat data/demo_accounts.txt
```

输出形如：

```
分析员 analyst  密码 xxxx
处置员 handler  密码 xxxx
只读   viewer   密码 xxxx
```

**把这四个账号连同 `admin` 一起写进提交文档**——四角色权限对比是白送的实用性分。

### 2.3 验证

```bash
curl -s http://127.0.0.1:8000/api/health | python -m json.tool
docker compose ps            # STATUS 应为 healthy
```

`/api/health` 会返回数据库状态、数据集条数、OCR 引擎、工具通道等，这是最省事的一眼体检。

## 三、裸机 systemd（Linux）

```bash
sudo apt update && sudo apt install -y python3.12 python3.12-venv libgl1 libgomp1
cd /opt && sudo git clone <仓库地址> campuspulse && cd campuspulse
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-ext.txt "gunicorn>=21.0,<23"
cp .env.example .env && sudo vim .env
```

`/etc/systemd/system/campuspulse.service`：

```ini
[Unit]
Description=CampusPulse
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/campuspulse
EnvironmentFile=/opt/campuspulse/.env
# 单 worker + 多线程：SQLite 写锁 / MCP 子进程单例 / 进程内缓存都要求这样
ExecStart=/opt/campuspulse/.venv/bin/gunicorn -w 1 -k gthread --threads 8 \
          -b 0.0.0.0:8000 --timeout 120 wsgi:app
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data:www-data /opt/campuspulse/data
sudo systemctl daemon-reload && sudo systemctl enable --now campuspulse
sudo systemctl status campuspulse
```

## 四、Windows 本地演示

```bat
start.bat
```

或手动：

```bat
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python tools\seed_demo_tickets.py --with-accounts --reset-passwords
set CP_AUTH=1
set AUTO_OPEN_BROWSER=1
.venv\Scripts\python run.py
```

内网其他机器访问：`set CP_HOST=0.0.0.0`，然后用 `http://<本机IP>:8000`。

## 五、反向代理（可选）

Nginx 需要两处调整，否则截图上传和 AI 流式回答会出问题：

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

    # 流式输出必须关缓冲，否则 SSE 会被攒成一坨再吐出来，
    # 前端"思考过程逐条出现"的效果就没了
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;

    client_max_body_size 20m;   # 截图一次可上传多张
}
```

## 六、部署自检清单

评审前一天照着过一遍：

```
[ ] /api/health 返回 ok，且 datasets 至少有 1 个非空数据集
[ ] 首页能打开，顶栏显示"历史快照 · 数据截至 X"（不是空白）
[ ] 用 admin 登录成功，四个账号都能登录且权限不同（viewer 看不到处置按钮）
[ ] AI 工作台提问一次，工具步骤正常出现、回答有引用角标
[ ] 数据页上传一张评论截图，能识别出文字并走复核流程
[ ] 证据页能检索、能点"据此建单"
[ ] docker compose ps 显示 healthy / systemctl status 显示 active
[ ] 服务器重启后服务能自动拉起（restart: unless-stopped 或 Restart=always）
[ ] 演示账号密码已写进提交文档，且不是 admin 的初始随机密码
```

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动后页面一直空白 | 首次 ETL 还在跑 | 看日志，25,699 条约需 10–20 秒 |
| AI 问答报"模型不可用" | `DEEPSEEK_API_KEY` 没配或额度耗尽 | 配 key；不配也会降级为规则陈述，不是白屏 |
| 截图导入提示"未检测到 OCR 引擎" | 没装 `requirements-ext.txt` | `pip install -r requirements-ext.txt` |
| `ImportError: libGL.so.1` | 缺 opencv 运行库 | `apt install libgl1 libglib2.0-0` |
| 日志出现 `database is locked` | 多 worker 抢 SQLite 写锁 | 改回 `-w 1` + 多线程 |
| SSE 变成一次性输出 | Nginx 缓冲了响应 | `proxy_buffering off` |
| 上传大图 413 | Nginx 体积限制 | `client_max_body_size 20m` |

## 八、资源占用参考

单机实测（25,699 条原始评论 → 1,803 条有效记录）：

| 指标 | 值 |
|---|---|
| 内存（含 OCR 扩展） | 约 480MB |
| 内存（仅核心） | 约 180MB |
| 磁盘（SQLite + 上传） | 约 40MB |
| 冷启动到可服务 | 12–20 秒（首次建库）；之后 2 秒 |
| 单轮 Agent 回答 | 3–8 秒（取决于工具步数） |

1 核 2G 的轻量服务器足够跑演示，不需要 GPU。
