## 三、修掉的 7 个问题

按"用户会多难受"排序。

### 1. 【严重】双击启动器，跑起来的是另一个系统

`start.bat` 第 68 行执行的是 `app.py`——V0 原型的单页大屏，不是 CampusPulse。
它没有清洗链路、没有 RAG、没有 AI 工具调用、没有安全闸。
新用户（包括评委自己试）最自然的动作就是双击 `start.bat`，拿到的却是完全另一套东西，
而且界面看起来"也挺像那么回事"，**很难意识到自己跑错了**。

- 修复：`"%PY%" app.py` → `"%PY%" run.py`，窗口标题同步改为 CampusPulse。
- 验证：默认端口 8000 起服务，`/api/health` 返回 `version 1.0.0`，页面标题「智能驾驶舱 · 高校舆情智能洞察平台」。
- 顺带：README 里"旧版可继续用"的措辞改成明确边界——**正式入口只有 `run.py`，答辩一律用它**。
- 踩坑记录：`start.bat` 是 **GBK 编码**，我第一次用 UTF-8 读写，把 271 个汉字变成了 `�`。
  已用同源的 `_bat_run.bat` 还原，并在 GBK 下重做替换。**中文 `.bat` 永远按 GBK 处理，别用 UTF-8 覆盖。**

### 2. 【中】切数据集后，"数据覆盖"还写着上一个数据集的时间

切到「2023 秋招季」，KPI 从 1,803 变成 2,567、图表全变了，但筛选栏右侧仍显示
`数据覆盖 2019-09-03 ~ 2026-07-07`（那是全量历史样本的范围）。
顶部徽标已经正确变成"数据截至 2023-11-20"，于是**同一屏上两处时间自相矛盾**——
这是评委最容易抓住、也最难辩解的一类问题。

- 根因：`renderFilterBar()` 返回的 `{sync, apply}` 被直接丢弃，切数据集时没人刷新提示。
- 修复：core.js 保存该实例，`change` 时调 `sync()`。
- 验证：三个数据集分别显示 `2023-09-01 ~ 2023-11-20` / 同 / `2019-09-03 ~ 2026-07-07`。

### 3. 【中】证据页翻页、排序刷新就丢

翻到第 2 页，地址栏还是 `?dataset_id=...`，一刷新回第 1 页；也没法把"这一页的证据"发给别人复核。
根因有两层：`syncUrl()` 根本不接收参数（调用方传了也白传），`qs()` 又会把分页参数抹掉。

- 修复：`syncUrl(extra)` 支持页面私有参数；`qs()` 保留非筛选参数；导航链接只带筛选不带页码。
- 同时：从 URL 恢复排序时把下拉框一起回填，否则**数据和控件说的是两件事**。
- 验证：翻页 → `&offset=20`，刷新仍停在第 21–40 条；`?order=time_desc` 刷新后控件显示"按时间"。

### 4. 【中】AI 降级时，把原始报错 JSON 甩到界面上

key 失效时的提示原本是：
`已切换为规则路由并直接查询数据库。（http_401: {"error":{"message":"Authentication Fails, ...`
末尾连右括号都没有（被 `[:80]` 截断了）。老师只会得出一个结论——**系统坏了**。
而他真正该知道的是：数字还是数据库算的，只是分析没 AI 那么细。

- 修复：新增 `_ai_error_notice()`，把异常翻译成"人话 + 诊断码"，原始异常只进日志。
- 现在的文案：`AI 暂不可用（密钥无效或额度用尽），已切换为规则模式：后面的数字仍由数据库直接统计，口径与图表不受影响，只是分析的细致程度不如 AI。诊断码 auth。`
- 分类覆盖 6 种：auth / rate_limit / timeout / server / network / unknown，且 `1500` 不会被误判成 5xx。

### 5. 【低】日期校验文案里多一个空格

`开始 日期格式应为 YYYY-MM-DD` → `开始日期格式应为 ...`。
单看是小事，但这种"手滑痕迹"会传染成对系统整体可靠性的怀疑。

### 6. 【低】预热失败被静默吞掉，启动日志只有一行

`run_async` 里是 `except Exception: pass`；`print` 没带 `flush`，而 `app.run()` 会阻塞到进程结束，
于是重定向到日志时只能看到第一行。
结果就是：**预热成功你也不知道，失败你更不知道**——用户只觉得"第一次问怎么这么慢"。

- 修复：异常打 traceback（仍不阻断启动，预热只是优化）；`print(..., flush=True)`；结束时打汇总。
- 现在的启动日志：`预热完成: 728ms · 缓存命中 3/3 个数据集`。

### 7. 【低】首次导入 2.5 万条，十几秒里一个字都不说

端口已经起来、页面却查不到数据，不打日志就只能看着白屏强退。

- 修复：导入前报总量，每条报"原始 → 有效 + 耗时"。
- 现在：`[1/3] 导入 全量历史样本 · 2019-2026：25699 → 1803 条（2562ms）`，全部导入完 **3.4 秒**。

> 附：文档里规则条数一直写"17 条"，实际已是 20 条（D7 又补了 3 条反向语序规则）。
> 已在技术说明、演示脚本、README、架构图、进度文档中统一为 20 条。

## 五、剩余风险（诚实清单）

这些**不是 bug**，是当前形态下的边界。答辩被问到要能直接说。

| 风险 | 现状 | 一句话应对 |
|---|---|---|
| 没有登录与权限 | 任何人打开就能看全校舆情 | 现为单机私有化部署；多用户需加账号体系与数据权限分域 |
| 前端请求无超时/取消 | AI 卡住时前端一直转，只能刷新 | 后端有 45 秒超时兜底；前端补 AbortController 是下一步 |
| 多轮追问不继承上一轮口径 | 问"宿舍"再问"这些问题的建议"，会回到全量统计 | 现在会明说"没有针对性建议"，不会编；继承筛选待做 |
| SQLite 单写者 | 4 并发写入正常，再多会排队 | 全校级并发应换 PostgreSQL；当前数据量（1,803 条）毫无压力 |
| RAG 引用校验只记录不阻断 | 数字不匹配会**撤回重答**，但引用编号不匹配仅记录 | 数字层是硬拦截，引用层是报告——这个差别要主动说清楚，别说成"都拦了" |
| 全套自检靠手动跑 | 没有 CI | 5 个脚本 + 一条命令即可，答辩前手动跑一遍够用 |

## 七、体检过程中值得记住的四个坑

1. **中文 `.bat` 必须按 GBK 处理**——用 UTF-8 覆盖会把全部中文变成 `�`（这次真踩了，271 个字符）。
2. **`print` 不带 `flush` + 服务阻塞 = 没有日志**。重定向到文件时是全缓冲，要等进程结束才吐出来。
3. **正则别经过多层转义写入**。`\\b` 经过两次转义会变成退格控制字符 `\x08`，正则静默失效。
4. **"图表空白"不要只看左上角**。折线图左上角本来就是坐标轴留白，按 60×60 采样会把好图误判成空图。
