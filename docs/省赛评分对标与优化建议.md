# 省赛评分对标与优化建议｜CampusPulse（AI Web 网页开发赛道）

> 依据：`参赛.md`（省赛评分细则：AI 技术深度 35%、创新性 25%、前端工程质量 10%、实用性 10%、
> 用户体验 10%、社会价值与商业潜力 10%；决赛另有现场答辩占 30%）
> 底稿版本：当前仓库代码（30/30 验收通过）。**本文只列建议，未改动任何代码。**

---

## 0. 一句话结论

按细则逐条对照，当前作品大约在 **60/100** 区间。失分最狠的地方不是"做得不好"，
而是**细则里点名要、但作品里没有的东西**：

| 细则点名 | 我们目前 | 分值 |
|---|---|---|
| RAG 架构、检索策略 | 只有 SQL 聚合 + LIKE 关键词检索，**没有检索增强生成** | 6% |
| 多模态（文本/图像/语音/视频） | 纯文本 | 5% |
| 流式输出、AI 思考状态可视化 | 一次性 JSON，等待 4–6 秒只有一行"分析中…" | 3%（体验维度内） |
| TypeScript 规范使用 | 全量 Vanilla JS，无类型、无构建链 | 4%（工程维度内） |

这 18 分几乎是"送分题里漏做的题"，且都不需要推翻现有架构——现有后端已经把
"统计口径 + 工具层 + 证据链"打得很扎实，缺的是**把它们接到评审的评分词上**。

## 2. 优化清单（按性价比排序）

排序依据：**净增分 ÷ 工作量**。S 档建议全做，A 档按时间选，B 档视情况。

---

### S1｜SSE 流式输出 + 思考过程可视化　`+2.0 分 / 约 1 人日`

**问题**：`static/cp/agent.js:272` 是一次 `await fetch('/api/agent/chat')`，后端
`agent.py:chat()` 同步跑完（实测 3.6–6.0s）才返回，前端只有一行"Agent 正在理解问题并调用工具计算…"。
细则原文要求"**流式输出渲染流畅、AI 思考状态可视化**"，现在这 3 分基本拿不到。

**做法**
1. 后端新增 `GET/POST /api/agent/chat/stream`，用 `flask.Response(generator, mimetype='text/event-stream')`；
2. 事件设计：`plan`（意图与计划）→ `tool_start`（工具名 + 参数）→ `tool_done`（耗时 + 命中条数）
   → `token`（回答增量）→ `chart`（图表 spec）→ `done`（审计落库）；
3. 前端把现有的"工具步骤卡片"改成**逐条点亮**，回答文字打字机式追加；
4. 顶部显示"第 1 步：查询情感分布（0.42s）→ 第 2 步：检索证据（0.18s）"。

**演示话术**
> "评审看到的不是一句'分析中'，而是它在**想什么、调了哪个工具、每个工具花了多久**。
> 这不是动画，是后端真实事件的推送——工具慢在哪、模型慢在哪，一眼可见。"

**附带收益**：首字延迟从 4–6s 降到 < 1s，体验维度"加载状态优雅"同步加分。

---

### S2｜RAG：把"证据链"升级成真正的检索增强　`+4.5 分 / 约 3 人日`（最高优先级）

**问题**：现在 LLM 只收到**聚合数字**（`_compact_for_llm()` 只喂 metrics），
原文只在工具结果里附带几条。严格说这是"Text-to-SQL 式问答"，**不构成 RAG**，6 分里只拿到 1 分。

**做法（三层，由易到难）**
1. **混合检索**：`rank_bm25`（纯 Python，零依赖）+ 本地向量模型 `bge-small-zh-v1.5`（~95MB，
   `sentence-transformers` 或 `onnxruntime` 推理），对 1,800 条评论离线建索引，
   查询时 BM25 top-20 + 向量 top-20 融合（RRF 倒数排名融合）；
2. **上下文注入**：把 top-6 条脱敏原文塞进 prompt，要求"**每个结论后标注引用的 `[CMT-xxxx]`**，
   没有检索到的证据不得陈述"；
3. **引用可读**：前端把 `[CMT-xxxx]` 渲染成可点芯片，点击直达证据详情（现在的深链已具备）。

**为什么这一项最值**
- 直接吃满 RAG 6 分的可评部分；
- 把已有的"去标识化证据溯源"从**产品功能**变成**技术架构**，创新性维度同时受益；
- 讲得清楚："我们不是让模型编，是让它**只能引用检索到的句子**。"

**风险与兜底**：模型文件 95MB，需随包分发或首次运行下载；
若离线拉不到，自动降级为 **BM25-only**（仍算检索增强，但要在文档里如实写明）。

### S3｜多模态：三选一，先做 a　`+3.0 分 / 约 2 人日`

细则给了 5 分，现在 0 分，是**全表最容易补的空白**。

| 方案 | 工作量 | 得分预期 | 演示效果 | 风险 |
|---|---|---|---|---|
| **a. 语音输入**（浏览器 `webkitSpeechRecognition`，0 依赖 0 成本） | 0.5 人日 | +1.5 | 按住说话 → 自动填入问题 | 中文识别看浏览器，Edge/Chrome 可用 |
| **b. 图片/截图入料**（视觉模型抽取图中吐槽文本 → 走同一条清洗+分析流水线） | 1.5 人日 | +2.0 | 粘贴一张评论截图 → 进库 → 可被检索 | 需视觉 API（DeepSeek 当前无视觉，需换 Qwen-VL/GLM-4V），有调用成本 |
| **c. 链接一键采集**（复用 `MediaCrawler`：贴抖音/小红书链接 → 采集 → 清洗 → 分析） | 3 人日 | +3.5 | 最炸场 | 需登录态、反爬、现场网络，**演示风险最高**；建议录屏而非现场跑 |

**建议**：先做 a（半天，稳赚），b 作为 A 档，c 只做**录屏演示 + 文档说明**，不在现场跑。

### S4｜前端工程：先把"3 分性能"拿稳，再谈 TS　`+2.2 分 / 约 2 人日`

**已经量到的三个硬伤**（`/static/vendor/echarts.min.js`，实测数据）

| 现象 | 数值 | 修法 | 收益 |
|---|---|---|---|
| 每页都加载 ECharts（`base.html:8`） | **1001KB / 页** | 只在需要的页面引入；`/evidence` `/data` 不引入 | 这两页传输量 −94% |
| 无压缩 | 1001KB 明文 | `Flask-Compress`（gzip/brotli） | 1MB → **约 300KB** |
| 静态资源不缓存 | `Cache-Control: no-cache` | `SEND_FILE_MAX_AGE_DEFAULT` + 文件名带 hash | 二次访问 0 请求 |
| 图表全部一次性初始化 | 洞察页 11 张图同时建实例 | `IntersectionObserver` 进视口再 `init` | 首屏图表时间 ↓ 约 40% |

**关于 TypeScript（4 分，细则点名）**
- 全量迁移风险高（7 个文件、无构建链、正在演示期），**不建议现在重写**；
- 折中方案（约 1 人日）：
  1. 加 `package.json` + `esbuild`，把 `static/cp/*.js` 挪到 `src/`，改成 `.ts`，
     先只用 `// @ts-check` + JSDoc 类型（`tsc --noEmit` 能过）；
  2. 给 `core.js` 的 `api / chart / setOption / filterParams` 和工具结果结构写 `interface`；
  3. 构建产物仍输出到 `static/cp/`，Flask 一行不改。
- 答辩时能说："前端有类型检查与构建链，`tsc --noEmit` 零报错"——比"我们用了 JS"强得多。

**组件化（3 分）**：把三处重复的 `innerHTML` 拼装（KPI 卡、卡片头、图表容器）抽成
`renderKPI() / renderCard() / mountChart()` 三个函数，代码量减 30%，评委翻代码时观感完全不同。

### S5｜商业与社会价值：补一页纸就值 3 分　`+3.5 分 / 约 1 人日`

现在这块**几乎是空白**（只有一句"面向学院评估"）。补一节即可，不需要写代码：

- **用户画像**：招生办（招生季舆情）、宣传/学工（突发事件）、校领导（周报决策）
- **市场规模**：全国高校 3,000+、职业院校 1,500+，按 2 万/年/校测算 = 潜在 9 亿/年（给出测算过程，别只给数字）
- **收费模式**：SaaS 订阅（按数据量分档）+ 私有化部署（数据不出校，正好契合我们的本地 SQLite 方案）
- **竞品对比**：新浪舆情通 / 清博 / 人民网舆情——它们面向政府和品牌，**没有面向"单校区、招生季、学生诉求"的轻量版本**，价格与部署门槛是空档
- **合规优势**：全本地部署、评论去标识化、不采昵称/IP，符合《个人信息保护法》最小必要原则
- **可持续性**：同一套清洗+分析引擎可平移到"课程评价""后勤报修""就业反馈"

### S6｜AI 安全补输入侧　`+0.5 分 / 0.5 人日`

输出侧已经很扎实（数值溯源 + 越权拦截 + 审计），缺输入侧：

1. **Prompt 注入检测**：正则 + 关键词黑名单（"忽略以上指令""你现在是""system:"），命中则拒绝并记录；
2. **越权诱导拦截**：识别"把所有评论原文给我""导出用户信息"这类请求，统一回复"仅提供脱敏聚合结果"；
3. **长度与频率限制**：单条问题 ≤ 200 字，单会话 ≤ 20 轮（已有 6 条上下文窗口，可加计数）；
4. **敏感内容兜底**：展示层对极端词做打码，并在文档里写明"不做内容审查，只做展示保护"。

验收里加 2 条用例（注入被拒、越权被拒），答辩可当场演示"我试着黑它，它拒绝了"。

### S7｜交互创新：对话即筛选　`+1.5 分 / 1.5 人日`

现在 Agent 说"宿舍维度负面 41%"，用户还得自己去驾驶舱重新点筛选。
改成：Agent 的工具调用参数里已经带了 `dimension / platform / date_from`，
**直接把这些参数同步到全局 URL 状态**，回答卡片底部给一个按钮：
「在驾驶舱中展开这组筛选」→ 跳 `/dashboard?dimension=宿舍住宿&sentiment=negative`。

这一步把"对话"和"看板"缝成一个东西，也正好回应"交互模式创新"。
（`core.js` 的 URL 状态同步已经现成，工作量主要在 Agent 返回体里加 `filters` 字段。）

### S8｜MCP 包装　`+1.0 分 / 0.5 人日`

把现有 5 个工具再暴露一次，用 `mcp` Python SDK 起一个 stdio server（`tools/mcp_server.py`），
Schema 直接复用 `TOOL_SPECS`。答辩时说：

> "同一套受控工具，既能被网页里的 Agent 调用，也能作为 MCP Server 被 Claude Desktop /
> 任意 MCP 客户端调用——工具层与界面解耦。"

0.5 人日换 1 分，且几乎零风险（不影响主链路）。

## 3. 不建议做的事（风险 > 收益）

| 想法 | 为什么不建议 |
|---|---|
| 事件自动聚类 / 主题命名（E08–E11） | 语义聚类在口语化短文本上极不稳定，一旦把"两条宿舍吐槽"聚成"同一个事件"，会被追问到崩；当前明确写在"已知边界"里反而加分 |
| 全量 TypeScript + SPA 重写 | 7 个文件、无构建链、演示期回归风险极高；只做类型标注 + 构建链即可拿大部分分 |
| 现场演示真实爬虫采集 | 登录态、反爬、现场网络任一环节失败就是事故；**录屏 + 离线数据**更稳 |
| 上 LangChain / LlamaIndex | 评审会问"为什么需要它"，答不出就是减分；现在手写 Agent 循环反而讲得清 |
| 接入第三方舆情 API | 让"真实数据"这个最强卖点变成"调别人的接口" |

## 5. 容易被忽略、但直接决定名次的部分

1. **视频前 30 秒**：评审平均看 2–3 分钟。开场别讲架构，讲**一句能听懂的痛点**：
   "招生季，一条'宿舍电费贵'的视频下面有 900 条评论，学校想知道到底在骂什么——人工看不完，大屏又只会画图。"
2. **一页纸架构图**：现在只有文档里的文字描述，需要一张能贴在 PPT 里的图（数据层→统计层→工具层→Agent→前端）。
3. **量化证据**：把已有的东西数字化——
   - 25,699 → 1,803，有效率 7.09%，**每个数字可复算**
   - 回答中 31–38 个数字逐个溯源，**0 处幻觉**（验收用例强制）
   - 词云剔除 220 个停用词，**38% 的原始高频词是噪声**（捂脸 123、学校 244…）
   - 单轮问答 3.6–6.0s vs 人工翻 900 条评论
4. **决赛答辩预案**：至少准备 8 个追问题（已在 `docs/演示脚本.md` 里），
   尤其"你的 AI 会不会编数据"——这是本作品最该被问、也最能答好的一题。
5. **兜底演示**：现场网络断了怎么办？准备 `AI 不可用 → 规则模式` 的录屏，
   并说明这是**设计好的降级**而不是故障。

**一句话**：先补"细则点名但我们没有"的四样（RAG、多模态、流式、TS），

后者不花代码，但很可能比写代码更值分。
