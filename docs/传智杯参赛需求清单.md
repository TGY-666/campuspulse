## 三、需求清单

按「优先级 ÷ 工时」排序。**P0 不做会直接影响资格或扣大分，P1 是加分项，P2 只改材料和叙事。**

### P0 · 准入项（不做等于白做，必须 11-06 前完成）

#### P0-1　建立 git 仓库并重构为细粒度提交历史
- **为什么**：官方硬要求"完整、细粒度的 Git 提交历史，禁止一次性提交"，且应用于原创性核查。当前项目**完全没有 git**。
- **做什么**：
  1. `git init`，先写 `.gitignore`（见 P0-2）
  2. **按模块分批提交**，不要 `git add -A` 一把梭：配置层 → 数据清洗 → 分析层 → RAG → Agent → 前端基础 → 各页面 → 多租户 → 工单 → 引用核验 → 测试与验收脚本 → 文档
  3. 每次提交信息写清"改了什么 + 为什么"，与 `docs/` 里的 Sprint 记录（S0→S4）和 `.workbuddy/memory/` 逐日日志对得上
  4. 在 README 里**主动披露**："代码仓库于 2026-11-03 建立，项目开发轨迹以 `docs/P2能力扩展需求规格说明书.md` 的 Sprint 记录与逐日工作日志为准"
- **红线**：**不要伪造提交时间戳**（`--date` 改历史）。文件 mtime 与 commit 时间对不上，反而比"仓库建得晚"更可疑。如实说明 + 文档佐证，比伪造安全一百倍。
- **工时**：1 天　**加分**：0（但决定能不能进评审）

#### P0-2　密钥与敏感信息清理
- **为什么**：官方明写"API 密钥等敏感信息不得出现在公开仓库中，须通过环境变量配置"。
- **做什么**：
  1. `.gitignore` 必须包含：`.env`、`data/*.db`、`data/uploads/`、`__pycache__/`、`*.log`、`screenshots/`（若含校内信息）
  2. 新建 `.env.example`（只有 key 名和空值，作为环境变量模板）
  3. 提交前用 `git log -p | grep -i "sk-"` 自查一遍历史里有没有漏
  4. 如果这个 key 曾在任何公开场合贴出过，**换 key**（当前 key 已在会话中出现过）
- **工时**：0.5 天　**加分**：0（漏了可能直接判违规）

#### P0-3　README 按官方六要素重写
- **为什么**：README 是评审第一入口，官方对内容有明确清单。
- **必须包含**：项目介绍 / 技术架构（**要有一张架构图**）/ 安装运行指南 / 环境配置说明（引 `.env.example`）/ 团队信息（角色 + 分工）/ 验收命令
- **现有基础**：README 内容已经很厚，但偏"内部维护手册"（大量验收数字），需**重排为"外部读者视角"**：前 30 行讲清"这是什么、解决谁的什么问题、技术亮点三个"，验收细节下沉到附录

### P1 · 加分项（按分数密度排序，11-14 前完成）

#### P1-1　多模态：截图评论导入（**最高优先级**，+3 分）
- **为什么**：多模态 5% 现在只拿 1 分，是**全表最大单点缺口**；而"多模态"在细则里只要求"集成多种模态且融合自然"，不要求炫技。
- **做什么**（最小闭环，2–3 天）：
  1. 在 `/data` 页"导入"旁加"上传截图"入口，接受 PNG/JPG
  2. 视觉模型识别：优先用**本地 PaddleOCR**（离线、零成本、数据不出校，符合项目调性）；无 OCR 环境时降级调用支持视觉的 API
  3. OCR 结果 → 解析成 `{content, create_time?, platform}` → 走**已有的** ETL 清洗管线入库
  4. 页面上明确标注"本条来自截图识别，置信度 xx，需人工复核"，与项目一贯的"口径诚实"风格一致
- **为什么这个方案好**：抖音/小红书的真实舆情工作里，**截图比 API 更常见**（学生截图发群里）。这个功能不只补分，还补了场景真实性——招生办收到的截图、家长群的转发图，现在系统吃不下。
- **验收**：上传 3 张真实截图 → 识别出文字 → 进入数据集 → 可在证据页检索到 → 带"截图来源"标记
- **工时**：3 天　**加分**：+3（1 → 4）

#### P1-2　MCP Server 化（+1.5 分）
- **为什么**：细则明写"是否通过 MCP 协议或 Function Calling"，现在只有后者，拿不满 4%。
- **做什么**（1 天）：
  1. 用官方 `mcp` Python SDK 起一个 stdio server，把现有 6 个只读工具暴露为标准 MCP tools（`list_datasets`/`aggregate`/`retrieve_context`/`trend`/`evidence`/`charts`）
  2. 让 Agent 的工具层支持"本地直调 / MCP 远程调"双通道，配置项切换
  3. 文档里写一句"同一套工具既支持内置 Function Calling，也可通过 MCP 被 Claude Desktop / Cursor 等外部客户端复用"——这句话本身就能拿分
- **工时**：1 天　**加分**：+1.5（2.5 → 4）

#### P1-3　前端渐进式类型化（+1.5 分）
- **红线**：**不要全量重写为 TS**。3,725 行原生 JS 在 16 天内转 TS，必然引入回归，而这项只有 4 分。
- **折中方案**（1.5 天）：
  1. 加 `package.json` + `typescript` + `checkJs`
  2. `jsconfig.json` 开 `checkJs: true`、`strict: false`，先让**通过**而不是"全绿"
  3. 给 `core.js`（公共层）和 `agent.js`（最复杂）补 JSDoc 类型注解，覆盖 fetch 封装、事件分发、verdict 结构
  4. 把 `tsc --noEmit` 加进验收脚本，固化"类型检查通过"
  5. 文档如实写："采用 JSDoc + checkJs 渐进式类型方案，核心公共层已全量注解，页面层逐步覆盖"
- **工时**：1.5 天　**加分**：+1.5（1 → 2.5）

#### P1-4　前端性能三项（+0.8 分）
- **做什么**（0.5 天，都很便宜）：

  2. 词云图库 `echarts-wordcloud.min.js`（16KB）改为**首屏不加载**，进洞察页再动态注入
  3. 非首屏图表容器 `IntersectionObserver` 懒初始化（ECharts 实例化是主要卡顿源）
  4. 用 Lighthouse 录一次前后对比数据，写进文档
- **工时**：0.5 天　**加分**：+0.8（2 → 2.8）

### P2 · 叙事项（不写代码，只改材料，同 P0-4 一起做）

#### P2-1　商业潜力章节（+1.5 分）
- **现状问题**：现在定位是"单校区工具"，商业潜力只能拿 2.5/5。但项目**已经有真正的多租户隔离**（M1：contextvars 租户上下文、32 项越权矩阵拦截、23 接口 0 漏写）——这是 SaaS 化的技术底座，只是没说。

  - 路径一：**校级 SaaS**——一套系统多校区部署，数据严格隔离（已有能力，可现场演示切换租户）
  - 路径二：**院校联盟**——同城/同省民办高校共享分析模型，各自数据不出域
  - 定价：按校区年费（对标舆情监测 SaaS 的 1/10 价位）+ 私有化部署许可
  - 市场规模：全国 3,000+ 高校，若 1% 渗透 × 年费，给出算式而不是空话
- **关键**：**不要吹"我们比专业舆情公司强"**，要讲"专业产品贵且不贴校园场景，我们做窄而深"

#### P2-2　创新点清单（+1.5 分）
- 官方要求"须明确列出技术创新点与应用创新点"，现在散落在各处，需要提炼成 3+2 条，每条一句能被记住的话：
  - 技术①：**引用核验六态**——AI 说的每个数字都要过溯源校验，对不上就整段改成规则陈述并标注，宁可少说不可乱说
  - 技术②：**8 状态处置工单机 + 工作小时 SLA**——跳步返回 409，时间线 append-only 由数据库触发器强制
  - 技术③：**零依赖混合检索 RAG**——BM25 + 同义扩展 + 字符 n-gram 向量三路召回，无需向量数据库
  - 应用①：**评论 → 证据 → 工单闭环**，把"看到问题"变成"有人管、有留痕"
  - 应用②：**每个数字带分母**，用口径诚实换取部门间的可信沟通
